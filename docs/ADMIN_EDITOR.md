# Admin editor

## Existing model before the editor

TDM kits are stored in `tdm_kits.txt` as global and per-map RED/BLUE lists. Each kit has a name, BOMB cost, and slot-indexed item records for 36 main inventory and four armor slots, including item NBT. `/tdm kit add` captures the administrator's current inventory, `/tdm kit remove` deletes a numbered direct kit, and gameplay falls back to global kits when a map has no direct kits for that team.

TDM maps are stored in `TDMData` world saved data. A map currently owns its name, mode and match settings, RED/BLUE/FFA spawn positions, and two BOMB site cuboids. Spawns store integer position and dimension, without rotation. Maps currently have no world field or map boundary. `/tdm map` provides creation, deletion, selection, settings, spawn additions/clearing, and BOMB site corner edits. Legacy global spawns remain a fallback.

Clowder SAFEZONE and WARZONE are chunk zoning values in Clowder territory data, edited through `/xc setclaim` radius/shape commands. They are not TDM maps or faction claims. The existing border effect sends temporary colored line particles to clients; JourneyMap has a separate claim overlay. World border exemptions use a separate per-admin wand corner selection and `EarthBoundarySavedData`.

Admin permissions were level 4 for `/tdm` administration and level 3 for `/xc` world border/zone administration. Existing commands remain server authoritative.

## Editor architecture

`/tdm editor gui` opens one draggable admin panel with Maps, Kits, Spawns, Areas, and Settings pages. Its position is retained for the client session. The panel displays a bounded server snapshot, including one selected kit's 40-slot preview and nearby Clowder SAFEZONE/WARZONE chunks. Its area preview is client-rendered inside the panel; the active selection also appears in a small HUD preview while the panel is closed. Neither preview writes map bounds as Clowder claims. Map bounds are an optional map-owned cuboid added to existing TDM world saved data. They act as a visual boundary until an administrator enables that map's optional match border. Maps still have no single world field: spawns each retain their dimension, and bounds and BOMB sites have their own dimension.

GUI actions carry an expiring server-issued editor token. The server rechecks operator permission, current dimension, map identity and revision, and selected direct-kit identity before invoking the same authoritative command paths used by chat. A stale panel action is rejected and the panel is refreshed. Destructive GUI buttons require a second click. Existing commands remain available for recovery and direct administration.

`TDMAdminKitEdit` owns an explicit per-admin inventory lease. Only a direct RED/BLUE kit can be loaded, in creative mode, outside competitive TDM participation, with an empty cursor and no other container open. The lease snapshots the original 36 main and four armor slots, plus the kit's exact in-memory identity and serialized revision. `/tdm kit commit` rechecks permission, dimension, mode, participation, cursor, and kit revision, saves the current slots using the existing item/NBT format, and restores the original inventory. `/tdm kit cancel` restores it without saving. Logout, death, dimension change, permission loss, mode change, other-container opening, timeout, and server unload cancel it. Item toss, pickup, and world/entity interaction are blocked during the lease. This Minecraft 1.7.10 kit format has no offhand slot. Clone copies the serialized kit record exactly; rename and cost edits change only their respective metadata.

`AdminSelectionManager` owns one typed selection per administrator. `MAP`, `BOMB_A`, and `BOMB_B` require level-4 TDM authorization and an existing map identity; `SAFEZONE`, `WARZONE`, `WILDERNESS`, and `BORDER_EXEMPT` require level-3 Clowder authorization. All types share A/B point capture, dimension checks, status, cancellation, preview state, validation, and typed commit. The item registered under the legacy `world_border_wand` ID is displayed as the Admin Selection Wand. Starting any type automatically gives one when the inventory has room and none is already carried. Its left and right block-click events provide actual server-observed block coordinates for A and B to the active session; right-clicking air does not select a point. The item carries no selection authority or target NBT and stays in the inventory after the session, so cleanup cannot delete an existing item. A full inventory leaves the selection active and tells the admin how to obtain the wand after making room. `/xc worldborder wand` starts `BORDER_EXEMPT` when no context exists and can reissue a missing wand without changing another active type. Existing `/xc setclaim` radius commands remain. `/tdm map bombsite` corner commands now feed the shared selection and commit once both corners are set; the previous saved site remains active until then. Clowder zone selection commits through the existing chunk zoning storage and keeps its 51-by-51-chunk maximum. Map bounds and BOMB sites commit only to TDM data.

Wand clicks run on the server through `PlayerInteractEvent`; the client sends no type, map name, or point coordinates in a custom wand packet. The point setter checks current permission, dimension, and map object identity before changing the session. It sends a read-only A/B snapshot to the client after each change; the Areas panel and the small in-world HUD preview update from that snapshot without reopening the GUI. Selection begin, cancel, commit, invalidation, logout, death, dimension change, and server unload clear the corresponding server state. Permission or target loss also invalidates it on the server tick. A wand without a session cannot edit or break a block. The preview is only a display and never mutates claims.

The configurable `Toggle Admin Editor` keybind is registered in Minecraft Controls under Xenofactions and defaults to F10. It sends `/tdm editor gui` through the ordinary server command path and therefore uses the same permission check. F10 closes an already open editor; `/tdm editor gui` remains available. The Areas page offers `Use wand` to close the panel while keeping the server selection active.

Map bounds can optionally enforce a match border. `/tdm map border <map> <on|off>` and the Maps page toggle require complete bounds to enable it; clearing bounds disables it. The default for existing saves is off. While TDM is running on the selected map, the owning server tick remembers each competitive player's last position inside the bounds and returns them there if they cross the X/Z footprint. The stored Y coordinates remain preview data and do not form a ceiling or floor. Spectators, nonparticipants, and creative TDM administrators are exempt. Enforcement is limited to the bounds' dimension, leaves players who were already outside until they enter or respawn, and retains no persistent player position. This is map-owned match behavior, independent of Clowder zoning and faction claims.

To add another area type, add a `Type` entry, its permission/target validation, and one commit branch in `AdminSelectionManager`; expose it through the appropriate command and editor button. Keep the new type's authoritative storage separate from preview state. The packet snapshot should include only bounded data needed to display it, and GUI actions should continue through a permission-checked server commit.

Map spawns remain RED, BLUE, or FFA. New or updated map spawns persist player yaw/pitch; older saved spawns lack rotation and continue preserving the player's facing when placed. The GUI can inspect, add, teleport to, update, and remove a numbered spawn. Global legacy spawns remain a fallback for maps without map-specific spawns.

## Map presentation and optional map mods

`/tdm overlay <on|off>` saves each player's persistent map overlay preference. During an active match it follows the selected map and dimension. Regular match players see map bounds, nearby public Clowder zones, their own team's spawn locations (FFA spawns in FFA), and both BOMB sites A and B on BOMB maps. Spectators and unrelated players receive no match overlay. Administrators may use `/tdm overlay on [map]` to inspect a named map, including all spawn types in their current dimension and nearby world-border exemptions, while retaining admin-only editing controls. The read-only overlay packet never carries kit or mutation authority. Changes to the map, team, dimension, or local zone are reflected by a bounded one-second server synchronization; turning the overlay off or leaving the world clears the client snapshot.

`/tdm boundaryview <on|off>` is a separate, saved level-4 administrator preference for a cyan in-world rendering of the selected map's horizontal bounds. An enabled map border also shows its nearby ground-following cyan spark boundary to active match players. Both use the same client particle effect as Clowder borders; F9 hides or shows all local border visuals. The map-border setting alone controls server-authoritative containment. The editor Settings page labels persistent overlay and in-world boundary separately; the Maps page labels enforcement.

JourneyMap 6.0.x clients use a JourneyMap API 2.0.0 plugin for faction claims, zones, map bounds, BOMB sites, and permitted spawns. The 5.2.x reflection hook remains for older clients. When the client cannot use either hook, the TDM overlay uses the standalone HUD map. The API is a compile-only dependency and is not bundled or required on dedicated servers. Existing editor and active-selection previews remain available to administrators.

Dynmap is server-side and separate from the in-game minimap. Its existing configurable city-claim marker set is supplemented by Xenofactions-owned `xenofactions_claims`, `xenofactions_zones`, and `xenofactions_tdm` sets. They publish other faction claims, SAFEZONE/WARZONE territories, and the enabled active map's bounds and BOMB sites, respectively. Exact spawn points are withheld from the public web map unless `showTdmSpawns=true` is set in Dynmap configuration. World-border exemptions are not published to the public web map because Dynmap marker-set visibility is not an authorization boundary. Dimension-to-Dynmap-world mapping must be configured for each published dimension. Deleted or deselected map markers are removed on the next configured marker refresh (default 30 seconds); changes to a viewed in-game overlay are synchronized within about one second. Dynmap and JourneyMap remain optional; the JourneyMap adapter loads only on the client.
