# Admin editor

## Map and kit storage

TDM kits are stored in `tdm_kits.txt` as global and per-map RED/BLUE lists. Each kit has a name, Search and Destroy buy-score cost, optional disabled gamemodes, and slot-indexed item records for 36 main inventory and four armor slots, including item NBT. Old kits have no disabled modes and remain usable in every mode. The stored buy-score cost is applied only in Search and Destroy. `/tdm kit add` captures the administrator's current inventory, `/tdm kit remove` deletes a numbered direct kit, and gameplay falls back to global kits when a map has no direct kits for that team.

TDM maps are stored in `TDMData` world saved data. One physical map owns shared bounds, Search and Destroy sites, match settings, supported voting modes, and a separate spawn set for each mode. The selected match stores a map name and gamemode independently. Spawns preserve dimension, integer position, yaw, and pitch. The old map `mode` field remains the default for commands that omit a mode and the migration source for old saves. Legacy global spawns remain a fallback only for that original default mode when its mode-specific set is empty.

Clowder SAFEZONE and WARZONE are chunk zoning values in Clowder territory data, edited through `/xc setclaim` radius/shape commands. They are not TDM maps or faction claims. The existing border effect sends temporary colored line particles to clients; JourneyMap has a separate claim overlay. World border exemptions use a separate per-admin wand corner selection and `EarthBoundarySavedData`.

Admin permissions were level 4 for `/tdm` administration and level 3 for `/xc` world border/zone administration. Existing commands remain server authoritative.

## Editor architecture

`/tdm editor gui` opens one draggable admin panel with Maps, Kits, Spawns, Areas, and Settings pages. Its position is retained for the client session. The panel displays a bounded server snapshot, including one selected kit's 40-slot preview and nearby Clowder SAFEZONE/WARZONE chunks. Its area preview is client-rendered inside the panel; the active selection also appears in a small HUD preview while the panel is closed. Neither preview writes map bounds as Clowder claims. Map bounds are an optional map-owned cuboid added to existing TDM world saved data. They act as a visual boundary until an administrator enables that map's optional match border. Maps still have no single world field: spawns each retain their dimension, and bounds and Search and Destroy sites have their own dimension.

GUI actions carry an expiring server-issued editor token. The server rechecks operator permission, current dimension, map identity and revision, and selected direct-kit identity before invoking the same authoritative command paths used by chat. A stale panel action is rejected and the panel is refreshed. Destructive GUI buttons require a second click. Existing commands remain available for recovery and direct administration.

`TDMAdminKitEdit` owns an explicit per-admin inventory lease. Only a direct RED/BLUE kit can be loaded, in creative mode, outside competitive TDM participation, with an empty cursor and no other container open. The lease snapshots the original 36 main and four armor slots, plus the kit's exact in-memory identity and serialized revision. `/tdm kit commit` rechecks permission, dimension, mode, participation, cursor, and kit revision, saves the current slots using the existing item/NBT format, and restores the original inventory. `/tdm kit cancel` restores it without saving. Logout, death, dimension change, permission loss, mode change, other-container opening, timeout, and server unload cancel it. Item toss, pickup, and world/entity interaction are blocked during the lease. This Minecraft 1.7.10 kit format has no offhand slot. Clone copies the serialized kit record exactly; rename and cost edits change only their respective metadata.

`AdminSelectionManager` owns one typed selection per administrator. `MAP`, `BOMB_A`, and `BOMB_B` require level-4 TDM authorization and an existing map identity; `SAFEZONE`, `WARZONE`, `WILDERNESS`, and `BORDER_EXEMPT` require level-3 Clowder authorization. All types share A/B point capture, dimension checks, status, cancellation, preview state, validation, and typed commit. The item registered under the legacy `world_border_wand` ID is displayed as the Admin Selection Wand. Starting any type automatically gives one when the inventory has room and none is already carried. Its left and right block-click events provide actual server-observed block coordinates for A and B to the active session; right-clicking air does not select a point. The item carries no selection authority or target NBT and stays in the inventory after the session, so cleanup cannot delete an existing item. A full inventory leaves the selection active and tells the admin how to obtain the wand after making room. `/xc worldborder wand` starts `BORDER_EXEMPT` when no context exists and can reissue a missing wand without changing another active type. Existing `/xc setclaim` radius commands remain. `/tdm map bombsite` corner commands now feed the shared selection and commit once both corners are set; the previous saved site remains active until then. Clowder zone selection commits through the existing chunk zoning storage and keeps its 51-by-51-chunk maximum. Map bounds and Search and Destroy sites commit only to TDM data.

Wand clicks run on the server through `PlayerInteractEvent`; the client sends no type, map name, or point coordinates in a custom wand packet. The point setter checks current permission, dimension, and map object identity before changing the session. It sends a read-only A/B snapshot to the client after each change; the Areas panel and the small in-world HUD preview update from that snapshot without reopening the GUI. Selection begin, cancel, commit, invalidation, logout, death, dimension change, and server unload clear the corresponding server state. Permission or target loss also invalidates it on the server tick. A wand without a session cannot edit or break a block. The preview is only a display and never mutates claims.

The configurable `Toggle Admin Editor` keybind is registered in Minecraft Controls under Xenofactions and defaults to F10. It sends `/tdm editor gui` through the ordinary server command path and therefore uses the same permission check. F10 closes an already open editor; `/tdm editor gui` remains available. The Areas page offers `Use wand` to close the panel while keeping the server selection active.

Map bounds can optionally enforce a match border. `/tdm map border <map> <on|off>` and the Maps page toggle require complete bounds to enable it; clearing bounds disables it. The default for existing saves is off. While TDM is running on the selected map, the owning server tick remembers each competitive player's last position inside the bounds and returns them there if they cross the X/Z footprint. The stored Y coordinates remain preview data and do not form a ceiling or floor. Spectators, nonparticipants, and creative TDM administrators are exempt. Enforcement is limited to the bounds' dimension, leaves players who were already outside until they enter or respawn, and retains no persistent player position. This is map-owned match behavior, independent of Clowder zoning and faction claims.

To add another area type, add a `Type` entry, its permission/target validation, and one commit branch in `AdminSelectionManager`; expose it through the appropriate command and editor button. Keep the new type's authoritative storage separate from preview state. The packet snapshot should include only bounded data needed to display it, and GUI actions should continue through a permission-checked server commit.

Map spawns remain RED, BLUE, or FFA within a selected gamemode context. FFA requires neutral spawns; TDM and Search and Destroy require their own RED and BLUE spawns. New or updated map spawns persist player yaw/pitch; older saved spawns lack rotation and continue preserving the player's facing when placed. The Spawns page switches context without duplicating map geometry, then inspects, adds, teleports to, updates, and removes only that mode's numbered spawns. The Maps page enables each voting mode independently. The Kits page can disable an individual kit in a mode; its saved buy score is shown as Search and Destroy only. Explicit sharing is available with `/tdm map spawnfallback <map> <mode> <source-mode|none>` and applies only when the target mode's own set is empty.

On first load of an older save, each map's former mode becomes its supported default. Neutral old map spawns move to the FFA set; team spawns move to the former team mode. Team spawns from an old FFA map are kept as unassigned legacy entries rather than guessed into TDM or Search and Destroy. Use `/tdm map legacyspawns <map>` to inspect them, then `/tdm map assignlegacyspawn <map> <number> <tdm|sd>` to place each into the intended set. The legacy global list is preserved. Pair votes and the selected mode are saved separately; old map-only votes resolve to that map's former default mode.

## Map presentation and optional map mods

`/tdm overlay <on|off>` saves each player's preference for additional match map details; the editor Settings page no longer has a Map overlay button. Every player in the selected map's dimension receives its boundary whenever map-border enforcement is enabled, even before a match starts. Both sites are also public while the active pairing is Search and Destroy and TDM is running. These public shapes appear automatically on JourneyMap, or on the standalone HUD map when JourneyMap cannot show them. The overlay preference adds nearby public Clowder zones and only the applicable active-mode spawn set; it does not hide the public boundary or sites. Administrators may use `/tdm overlay on [map]` to inspect a named map's bounds and nearby world-border exemptions; inactive map spawns and sites are withheld from that map overlay. The read-only packet carries no kit or mutation authority. Map, dimension, and data changes are synchronized within about one second; leaving the world clears the client snapshot.

`/tdm boundaryview <on|off>` is a separate, saved level-4 administrator preference for an in-world preview of selected map bounds. An enabled active map border automatically shows its nearby ground-following cyan sparks to all players in its dimension. Right Alt (configurable in Controls) toggles in-world Clowder and map-border effects and the standalone HUD map, and starts on. JourneyMap public shapes remain visible regardless of this key. The map-border setting alone controls server-authoritative containment. Stored map corners are inclusive blocks; all visual surfaces use the minimum block edge and the maximum block plus one. Clowder cells retain their legacy territory coordinates and render from their exact derived block edges.

JourneyMap 6.0.x clients use a JourneyMap API 2.0.0 plugin for faction claims, zones, active public map bounds and Search and Destroy sites, and applicable active-pairing spawn previews. The 5.2.x reflection hook remains for older clients. JourneyMap shapes follow world load, active map or mode changes, and overlay data changes; the standalone HUD map appears only when JourneyMap is unavailable or cannot accept the polygons. The API is a compile-only dependency and is not bundled or required on dedicated servers. Existing editor and active-selection previews remain available to administrators.

Dynmap is server-side and separate from the in-game minimap. Its existing configurable city-claim marker set is supplemented by Xenofactions-owned `xenofactions_claims`, `xenofactions_zones`, and `xenofactions_tdm` sets. They publish other faction claims, SAFEZONE/WARZONE territories, the enabled active map's bounds, and sites only during an active Search and Destroy pairing. Exact active-mode spawn points are withheld from the public web map unless `showTdmSpawns=true` is set in Dynmap configuration. World-border exemptions are not published to the public web map because Dynmap marker-set visibility is not an authorization boundary. Dimension-to-Dynmap-world mapping must be configured for each published dimension. Deleted or deselected map markers are removed on the next configured marker refresh (default 30 seconds); changes to a viewed in-game overlay are synchronized within about one second. Dynmap and JourneyMap remain optional; the JourneyMap adapter loads only on the client.

## Runtime test matrix

1. Configure one map for FFA, TDM, and Search and Destroy with distinct neutral, TDM team, and Search and Destroy team spawns. Confirm the vote GUI offers three separate options without duplicated bounds or map definitions.
2. Vote for FFA. Confirm neutral FFA spawn resolution at login, respawn, and round reset; no team or Search and Destroy spawn is selected. Sites and buy-score requirements remain inactive.
3. Vote for TDM on the same map. Confirm only its RED/BLUE set is used at login, respawn, team change, late join, spectator return, and round reset.
4. Vote for Search and Destroy on the same map. Confirm only its RED/BLUE set is used at round start, late join, and eligible respawn; both sites appear to an ordinary player and an admin on JourneyMap 6 and the standalone fallback. Normal buy-score costs apply.
5. Switch directly between modes on that map and verify the next round uses the winning exact pairing. Confirm stale sites and spawn markers disappear or change while the enabled shared border stays visible.
6. Leave a required set empty. Confirm the match refuses an unrelated mode's spawns; configure `spawnfallback` and confirm sharing occurs only then.
7. Open the editor's Spawns page for each context. Confirm list, category, position, yaw/pitch, add, update, teleport, remove, and clear act only on that context.
8. Load an old save with neutral, team, global, and ambiguous FFA-map team spawns. Confirm neutral and deterministic team entries migrate, global fallback remains for the old default mode, and ambiguous entries remain listed until assigned.
9. Enable spawn markers and compare JourneyMap 6 against the fallback HUD map on the active pairing. Confirm neither shows another mode's spawns and neither draws atop a usable JourneyMap.
10. Place spawns and bounds at negative coordinates near -1, -16, and -17 and in another registered dimension. Confirm dimension, yaw/pitch, exact block boundary edges, and map-border containment survive save/reload.
11. Reuse one kit in FFA and Search and Destroy. Confirm its saved cost is ignored in FFA, enforced in Search and Destroy, and a per-mode disable removes it from only that mode's picker.
12. With two players of different permissions, confirm the active enabled border and Search and Destroy sites are public by default, Right Alt toggles in-world border effects and the standalone fallback map without hiding JourneyMap shapes, and inactive map/editor state stays operator-only.
